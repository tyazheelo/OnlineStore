# Руководство по участию в разработке

## Архитектура

- Модули решения должны использовать согласованную структуру Clean Architecture: `API`, `Application`, `Domain` и `Infrastructure` — только если слой нужен модулю.
- Зависимости направляются внутрь: `Domain` не зависит от внешних слоёв; `Application` зависит от `Domain`; `Infrastructure` реализует контракты внутренних слоёв; `API` отвечает за HTTP/UI и композицию приложения.
- Бизнес-правила и сценарии использования не размещаются в `API` или `Infrastructure`.
- Контракты и реализации размещаются в слоях согласно их ответственности. Не добавляйте пустые проекты или файлы только ради формального единообразия.
- Регистрацию сервисов каждого слоя выполняйте согласованно через расширения DI; точка входа приложения отвечает за сборку модулей.

## Изменения кода

- Сохраняйте существующее поведение, если изменение архитектуры явно не требует иного.
- Не добавляйте абстракции, зависимости или файлы без практической необходимости.
- При изменении публичных контрактов обновляйте все места использования и связанные тесты.
- Перед завершением изменений проверяйте сборку и доступные автоматические тесты.

## Pull request

- Описывайте затронутые модули, архитектурные изменения и возможные несовместимости.
- Указывайте результаты сборки и тестов либо причину, по которой их не удалось выполнить.
